# Намкузу 𒉆𒆬𒍪 (NAM.KU₃.ZU) — предварительный концепт

> **Намкузу** — расширенный вики-движок для фэндомного и авторского контента, существующий в двух форматах: серверном (онлайн-вики) и десктопном (локальная база знаний).
> 
**Статус документа:** предварительная концепция
**Форматы:** Сервер, Десктоп (два самостоятельных продукта)
**Базовый стек:** Rust / Dioxus / SurrealDB / Tokio

## 1. Краткое описание

Намкузу — вики-движок, ориентированный в первую очередь на фэндомный и авторский контент: писателей и ворлдбилдеров. Он выпускается в двух форматах, которые решают разные задачи и не образуют клиент-серверную пару:

- **Сервер** — полноценная платформа для публичных онлайн-вики: сайт, где контент мира или фэндома ведётся сообща и доступен читателям через сеть.
- **Десктоп** — приложение для личной офлайн-базы знаний: вики-подход (страницы, связи, структура) для работы автора над своим миром целиком на его компьютере.

Общая идея обоих форматов — вики как способ организации знаний: страницы, связи между ними и структура, растущая вместе с материалом.

## 2. Два формата

|  | Сервер | Десктоп |
| --- | --- | --- |
| Назначение | Онлайн-вики | Офлайн-база знаний |
| Участники | Сообщество авторов и читателей | Один автор над своим проектом |
| Хранение | SurrealDB в обычном (серверном) виде | SurrealDB + SurrealKV, база знаний как локальный проект на диске пользователя |
| Работа | Онлайн, через сеть | Локально, без сервера |

### 2.1. Серверный формат

Серверный формат рассчитан на создание полноценных онлайн-вики: сайтов, где контент ведётся сообща и доступен читателям через сеть. База данных — SurrealDB, используемая в обычном режиме. Для сетевого слоя рассматриваются Axum и Tower.

### 2.2. Десктопный формат

Десктопный движок организует базы знаний как локальные проекты на диске пользователя. Хранилищем служит SurrealDB в связке с SurrealKV. Приложение работает полностью офлайн и не требует серверной части.

### 2.3. Независимость форматов

Сервер и десктоп не являются клиентом и сервером друг друга. Десктоп не синхронизируется с сервером и не является его «редактором»: это отдельные продукты, которые объединяет общая концепция, стек и аудитория.

## 3. Целевая аудитория

Основная аудитория — авторы фэндомного и оригинального контента: писатели и создатели вымышленных миров.

- Серверный формат — для тех, кто хочет открыть публичную или совместную вики по своему миру или фэндому.
- Десктопный формат — для тех, кому нужна личная рабочая база знаний по проекту.

## 4. Интеграция с Gaitha

Рассматривается интеграция с Gaitha — картографическим редактором, процедурным генератором и базой пространственных данных для вымышленных миров. Идея: показывать карты из Gaitha прямо в Намкузу.

- **Показ карт** — цель интеграции: карта из Gaitha отображается внутри Намкузу.
- **Редактирование из Намкузу** — рассматривается как возможность, но не обещается.

**Проект Gaitha внутри проекта Намкузу.** В десктопной версии рекомендуется
размещать проект карты Gaitha в папке проекта базы знаний Намкузу. Тогда
связь между ними можно определять по расположению файлов: Gaitha находит
проект Намкузу, поднимаясь по каталогам, а Намкузу обнаруживает карты в своей
папке и предлагает подключить их. Это упрощает настройку обмена данными,
переносимость (карты и знания переезжают и архивируются вместе) и выбор
нужного экземпляра при локальном взаимодействии.

Вложенность остаётся удобством, а не требованием: карта может лежать вне
проекта Намкузу, обслуживать несколько проектов или связываться с серверным
Намкузу, и тогда связь задаётся явной ссылкой. Файлы Gaitha размещаются
рядом с хранилищем Намкузу, а не внутри его служебных данных.

## 5. Технологическая основа

| Компонент | Технология |
| --- | --- |
| Язык | Rust |
| UI-фреймворк | Dioxus |
| База данных | SurrealDB (сервер — обычный режим; десктоп — вместе с SurrealKV) |
| Асинхронная среда | Tokio |
| Логирование и диагностика | Tracing |
| HTTP-слой сервера | Axum + Tower (под вопросом) |
| HTTP-клиент | Reqwest |
| Полнотекстовый поиск | Tantivy |
| Работа с изображениями | image |

Стек предварительный. Axum и Tower отмечены как возможные; остальные компоненты рассматриваются как основа проекта.

## 6. Открытые вопросы

Черновое описание фиксирует направление, но оставляет без ответа вопросы, которые нужно решить до проектирования:

- **Границы серверной вики.** Какие возможности серверной вики входят в первую версию, а какие нет: история правок, категории, шаблоны, права доступа, обсуждения, модерация.
- **Разметка и модель контента.** Язык страниц и способ связывания (вики-ссылки, структурированные поля, типы сущностей).
- **Общее ядро.** Будет ли у двух форматов общий крейт с моделью страницы и разметкой, и как он отделяется от слоя хранения.
- **Владение данными на десктопе.** Как пользователь получает свои данные вне приложения: экспорт в файлы или иной открытый формат.
- **Зрелость SurrealKV.** Нужно проверить его актуальное состояние для роли основного хранилища локальных проектов.
- **Поиск.** Роль Tantivy относительно встроенного полнотекстового поиска SurrealDB.
- **Перенос между форматами.** Нужен ли обмен проектами между десктопом и сервером (например, через архив) без полноценной синхронизации.
- **Лицензия и модель распространения** проекта и его компонентов.
- **Расположение проектов.** Правила обнаружения карты внутри проекта
  Намкузу, поведение при нескольких картах и при переносе проекта, а также
  запасной вариант для карты вне папки проекта.

* **Интеграция с Gaitha.** В каком формате (серверном, десктопном или обоих) она нужна и как карты попадают в Намкузу.

## Итоговое позиционирование

**Намкузу — вики-движок для авторов и ворлдбилдеров в двух самостоятельных форматах: полноценная онлайн-вики для совместной работы над миром или фэндомом и локальная офлайн-база знаний для личной работы автора.**

Общими остаются концепция вики, аудитория и технологический стек на Rust, Dioxus и SurrealDB; различаются задачи, хранилище и способ работы.
